# Visual acceptance

Apply only checks relevant to the requested output. Structural validation of this skill is not visual acceptance of generated art.

| Check | Evidence / failure |
| --- | --- |
| Brief | Subject, action, gaze, camera, count, and crop agree with the request. A prompt saying it is correct is not evidence. |
| Identity edit | Compare against the selected original for silhouette, proportions, markings, and distinctive details. Better polish does not compensate for identity drift. |
| Contact | Load-bearing parts meet intended surfaces; joints and overlaps make sense. A moving limb may be airborne when that is the intended action. |
| Ink grammar | Dark shapes remain readable; dots and hatching describe volume instead of obscuring it. Check small as well as full size. |
| Background | Requested paper, color, or alpha is present. A checkerboard drawing is not transparency. Retain white foreground details. |
| Brand / UI | Supplied marks and interface facts remain accurate. Do not certify a model-invented icon as official. |
| Integration | The real consumer loads the selected asset without stretching, clipping the subject, or inverting identity colors. Check affected appearances and sizes. |

Describe an unmet check plainly. Save source and candidate separately. After a focused repair, re-check the repaired region and any affected identity or composition. No numerical beauty score, unrequested variant quota, or mandatory new approval stage.

For reproducibility record the brief, reference roles, final prompt, known tool/model (or unavailable), file, generation/edit date, display environment, observed defects, and status. Exclude private paths or user data from public example records.
